## Summary
The paper adapts concept-erasure fine-tuning to Infinity-2B, a next-scale bitwise autoregressive text-to-image model. It trains with teacher-forced token pyramids taken from the original model's generation under the neutral prompt (VARE, Eq. 7). On top of that it adds a loss that masks tokens whose bits are already predicted correctly and applies bit-wise cross-entropy to the rest (L_FCE, Eqs. 8–10), plus a KL term on the neutral prompt (L_Pre, Eq. 11). Experiments cover nudity, one object class (plus ten Imagenette classes) and one style (Table 1, Table 2), robustness to adversarial prompt sets (Table 3), and ablations (Tables 4, 5, 7, 8).

**Protocol Sweep (quotes).** Training/test: "These test prompts are not included in the training set." (§5.1). No validation split is described anywhere. Selection: "we select a balanced threshold of 25% as the default parameter for all the tasks" (§5.3, Table 5, measured on Ring-A-Bell) and "we ultimately choose to optimize only the CA and FFN parameters" (App. C.2, Table 8, whose ASR/FID/CLIP row 7.4/32.8/31.3 equals the Table 5 α = 25 row and the Ring-A-Bell row of Table 3). Ring-A-Bell is also a reported evaluation set (Table 3). Neither choice is the best-scoring option on its table (α = 0 gives ASR 7.2; SA+CA+FFN gives ASR 7.1), both are justified by quality/compute trade-off, so this is not a leakage issue, but it is an undisclosed-split question.

## Strengths

### S1: A coherent, fully specified training recipe on a model people can run
§5.1, Table 6 and App. D give batch size, iterations, learning rate, precision, hardware, number of training pairs and the prompt-generation instruction. Everything runs on one A6000, which makes replication plausible.

### S2: Breadth of concept types, plus several useful secondary experiments
Table 1 covers nudity, an object and a style. Table 2 repeats the object setting over ten Imagenette classes, Table 7 tests multi-concept erasure, and Table 3 adds three adversarial datasets that were not used in training. This is more than many first-of-kind papers provide.

### S3: Arithmetic in the main summary tables is internally consistent
I recomputed the Table 2 average row: ACCe origin (99.0+95.0+94.2+95.4+62.8+95.2+16.4+100.0+100.0+20.6)/10 = 77.86 ✓ (77.9); ours ACCe 25.0/10 = 2.5 ✓; FID ours 321.0/10 = 32.1 ✓; CLIP ours 314.3/10 = 31.43 ✓ (31.4). The Church row of Table 2 matches Table 1 and Table 4 (4.4 / 75.7 / 31.5 / 31.6); Table 7 "Avg 10" matches Table 2 (2.5 / 32.1 / 31.4).

### S4: Ablations that probe design choices
Table 5 (α sweep), Table 8 (modules), Table 4 (loss components) and Fig. 8 (swapped losses) show the authors tested alternatives, and the α sweep honestly shows the erasure/quality trade-off.

## Weaknesses

### W1: The central methodological claim (C1) has no quantitative evidence
§4.1 states that "optimization with Eq. (6) introduces errors that accumulate progressively across scales", but the only evidence is Fig. 2 (left vs. middle vs. right column). There is no table with the vanilla loss (Eq. 6) or with auxiliary tokens from c* only, and the training prefix used by the vanilla variant (self-generated, teacher-forced from ground truth, or from the original model) is not specified. Every baseline in Table 1 is run inside VARE (§5.1: "the only difference between these converted baselines and our proposed S-VARE lies in the choice of loss function"), so the necessity of VARE is never measured. Teacher forcing against exposure-bias-style error is a standard device in autoregressive training; the paper should show *that* it is needed here and *why* the diffusion analogy fails.
- **Suggested Fix**: add rows to Table 1 or Table 4 for L_vanilla (Eq. 6), L_VARE with c* tokens only, and with c tokens only, on the same three concepts; define the training prefix of each. Cost: 3 variants × 3 concepts × ~1 A6000-hour ≈ 10 GPU-hours.

### W2: The "filtered" part of the loss is not isolated; the filter's value is unproven
Table 4 goes from MSE-style baseline to "+L_FCE", changing two things at once (distribution-space MSE → bit-wise cross-entropy, and masking of correctly predicted tokens). Table 5 varies α from 0 to 75 but includes no unfiltered cross-entropy row, and α = 0 still masks tokens whose bits are all correct. The α sweep shows a monotone ASR/quality trade-off (ASR 7.2 → 40.2, FID 33.6 → 31.4), i.e., a strength knob, not evidence that masking is better than unmasked CE at matched strength. The motivating observation (Fig. 3) is one heatmap for one prompt.
- **Suggested Fix**: add an unfiltered CE row (plus a CE row with a lower learning rate/iteration count matched to the same erasure level) and plot erasure vs. FID Pareto curves for filtered/unfiltered CE. ≈ 6 GPU-hours.

### W3: Baseline fairness cannot be verified
All baselines share Table 6's settings ("same parameter settings across all erasure tasks"), including lr 2×10⁻³ and 500 iterations that were evidently developed for S-VARE; there is no baseline-specific tuning described, and the baselines are re-implemented by the authors with undocumented code. UCE fails almost entirely (Table 1, ACCe 92.8) and the cause is asserted without test ("We attribute this failure to the strong robustness of the T5 text", App. A); a failure of a method that works on diffusion models with cross-attention text conditioning is as likely to indicate an adaptation issue. Importantly the Table 1 "AC-N" row equals the Table 4 "Baseline" row (9.8 / 68.9 / 35.3 / 30.6), and App. A says AC-N as written (Gaussian-noise target, Eq. 15) "loses its text-to-image generation capability", so the authors substituted Eq. 7. The "AC-N" baseline is therefore the VARE-MSE loss, not AC-N.
- **Suggested Fix**: relabel; report a small lr/iteration sweep for each baseline (≥ 3 learning rates, matched compute) and the UCE configuration (layers edited, preservation set). ≈ 15–20 GPU-hours.

### W4: Single run, single model, one concept per category in the main table; no uncertainty
Table 1, Table 3 and all ablations are single runs of one fine-tuning (no seeds, no intervals, number of test prompts and images per prompt not stated). Several comparisons that carry the narrative are small: FID 32.8 vs. 33.7–33.8 (NSFW), style ACC 8.2 vs. 12.8 (AC-M), object ACCe 4.4 vs. 3.8–4.2 (ESD, where the baseline is better). At large-generative scale a single run can be accepted by field norms, but these margins call for a bootstrap interval over test prompts or three seeds on one concept. Baselines are evaluated only on one object (church), one style (Van Gogh), one nudity term ("naked"); Table 2 shows the proposed method alone on ten classes.
- **Suggested Fix**: 3 seeds on church/naked/Van Gogh for all methods (≈ 30 GPU-hours), report test-prompt counts, and run baselines on at least three Imagenette classes.

### W5: Evaluation metrics are under-specified and partly in-distribution
"ASR" in Table 3 and Table 5 is never defined (detector, threshold, categories, prompt counts). Test prompts were generated by GPT-4o to "explicitly include the target concept" (§5.1), and training prompts contain a single fixed lexical item ("our prompts c* include only the term 'naked' and exclude other semantically similar words such as", App. D), so Table 1 mostly tests the training token. The adversarial sets in Table 3 are the only out-of-distribution evidence, and no baseline numbers are given there. NudeNet counts are the only nudity measure; no second detector or human check.
- **Suggested Fix**: define ASR, release prompts, add a held-out synonym set ("nude", "topless", "undressed") with baselines, and a second detector or small human audit on a random sample.

### W6: Reproducibility of the central equations
Eq. 9 and the text disagree on direction. The text says "ratio(·) denotes the percentage of the correct dimensions within tokens" and a token is excluded "if the percentage of incorrect bits is less than α", yet Eq. 9 reads I(ratio(L_CE ≥ γ) > α), where L_CE ≥ γ is a loss threshold (incorrect). Eq. 8 has no target term and no negative sign ("L_CE = log p_θ*(r_i | r<i^ori, c*)"), so which BSQ bits are regressed to is only given in prose (§4.2). No code, and no compute time is given although the conclusion stresses "safe and efficient deployment".
- **Suggested Fix**: restate Eqs. 8–10 with explicit target bits and the direction of the mask; release code.

## Summary
The paper targets a real gap: published concept-erasure methods (ESD, AC, FMN, UCE and successors) assume noise- or velocity-prediction diffusion models, whereas Infinity predicts bitwise tokens at increasing scales. The authors reuse the "difference of conditional predictions" idea, make it teacher-forced on the original model's tokens (VARE), and swap the regression loss for a masked bit-wise cross-entropy plus a KL preservation term. Reported results are strong against adapted diffusion-era baselines on one concept per category.

## Strengths

### S1: Well-motivated, timely problem
Safety interventions for next-scale models are largely missing; §1 and §2.2 correctly identify why MSE-on-noise losses do not carry over (probability-space targets, autoregressive dependence across scales). Infinity is the right model to study.

### S2: Losses are matched to Infinity's actual training objective
Using binary cross-entropy on bits and reusing Infinity's 0–30% bit self-correction range to set α = 25% (§4.2) is a principled design link between the model's training and the erasure objective, and App. C.3 (Fig. 8) at least probes the swapped alternative.

### S3: Fair-minded baseline taxonomy
§5.1 and App. A cover the four main diffusion families (attention-activation FMN, ESD-u/x, AC-M/N, closed-form UCE) and are open about what failed and why, which helps later work.

### S4: Evidence beyond training prompts
Table 3 uses real-user and adversarial nudity prompt sets (I2P, MMA, Ring-A-Bell) created for diffusion models; the paper states that "Since no adversarial attack benchmark currently exists for VAR models" (§5.2), an honest framing.

## Weaknesses

### W1: Positioning against autoregressive erasure is inconsistent
§2.2 states "existing approaches are constrained to the diffusion paradigm and are not directly applicable to VAR models", and §6 claims "the first effective framework for concept erasure in VAR-based text-to-image models". Yet the bibliography contains EAR (Fan et al., 2025, "Erasing concepts from unified autoregressive models"), whose benchmark recipe (ECGVF) the paper uses for training data (§5.1, App. D: "prior autoregressive concept erasure methods EAR"). EAR is never discussed in §2.2, never differentiated, and not compared. Per its abstract (kept result, arXiv June 2025) EAR targets raster/patch-level AR models and includes a thresholded loss-masking strategy that protects unrelated content, which is conceptually close to the paper's token-masking filter. The VAR-specific claim may still hold, since EAR addresses raster-order AR and not next-scale prediction, but the delta must be stated. This is a MAJOR (cited-but-undifferentiated) issue, not a missing required baseline: EAR is a recent preprint (< 6 months before the 2025-09-24 cutoff).
- **Suggested Fix**: add EAR to §2.2 and a novelty paragraph stating what differs (next-scale conditioning, bit-wise targets, teacher forcing); if feasible, adapt its masking to Infinity as an additional baseline.

### W2: The "first / only" scope claims are not backed
"Infinity-2B ... currently the only publicly available VAR model that supports large-scale text-to-image generation" (§5.1) is difficult to verify; other open scale-wise or hybrid models exist (e.g., Switti and HART, both verified on arXiv, the latter hybrid AR + residual diffusion), and the title and abstract ("closing the safety gap in autoregressive text-to-image generation") generalize from one model to a family. Without a second architecture (even class-conditional VAR on ImageNet) the framework's generality is untested.
- **Suggested Fix**: either evaluate on a second scale-wise model or retitle and narrow the abstract to Infinity.

### W3: Technical contribution is a thin delta over known erasure recipes
C1 is, operationally, teacher-forced distillation of the neutral-prompt prediction onto the target-prompt prediction (Eq. 7), a shared structure with ESD/AC and with standard AR distillation. C2 combines masked cross-entropy (a thresholded form of focal/hard-example weighting) and a forward-KL regularizer, both standard. This is acceptable for an application-driven paper at ICLR if the evidence for why each piece is needed is strong; at present (see Methodology review) it is not. The paper's reasons for failure of UCE ("T5 ... robustness") and of KL-for-erasure ("KL divergence imposes stronger constraints than quantized cross-entropy", App. C.3) are asserted, not tested.
- **Suggested Fix**: tone down causal statements or test them (e.g., T5 vs. alternative conditioning probe).

### W4: Missing comparison families for robust erasure in diffusion
The related work cites MACE, adversarial-preservation and contrastive approaches (§4.3) but compares only with the oldest four. Methods designed for robustness (e.g., adversarially trained erasure, STEREO, CVPR 2025) are the relevant references for the Table 3 robustness claim. These are context, not required comparisons, because they target diffusion models.

## Summary
From a deployment point of view, the paper offers a fine-tuning recipe that takes an open text-to-image VAR model and removes a named concept with roughly one GPU-hour of training on 50 prompt pairs (Table 6), at modest cost to benign generation (Table 1 FID/CLIP). The authors test three concept types and adversarial nudity prompts.

## Strengths

### S1: Very low-cost intervention
Table 6 (50 prompt pairs, 500 iterations, a single A6000) makes patching a deployed model for a newly identified harmful concept realistic, which is exactly the motivating scenario in §1 ("new undesirable concepts are identified after model training"). The multi-concept results in Table 7 point in the same direction.

### S2: Real-user and adversarial prompt coverage for nudity
Table 3 includes I2P, MMA and Ring-A-Bell, with reported drops in ASR on each (e.g., R-A-B 75.9 → 7.4), which is closer to moderation practice than a purely curated prompt list.

### S3: Concept types match real moderation categories
Nudity, copyright-adjacent style and object removal map onto three standard categories of policy-driven filtering (§1), and the style example is visually discussed with an honest caveat ("our method could occasionally be detected as a specific artistic style", §5.2).

### S4: Fine-tuned weights are a drop-in artifact
Because only CA+FFN weights change (App. C.2), the result is a checkpoint, not a runtime filter, which cannot be bypassed by removing a post-hoc classifier (§2.2 contrasts this with post-generation filtering).

## Weaknesses

### W1: Success is reported in detector counts, not in moderation terms
Nudity results rely on NudeNet counts (Sen., Com.), and the benign-content measure shows a large drop: Com. 112 → 57 (Table 1) and 419 → 146 on I2P (Table 3), i.e., roughly half or more of the benign body-part detections vanish. In a moderation setting, over-erasure of people (swimwear, athletes, medical contexts) is the practical failure. The paper treats this as success ("performs only below UCE"), though it is the weakest numbers in the table for "surgical".
- **Suggested Fix**: add a semantic-neighbour test: benign prompts for swimwear, medical anatomy, art history; report human or second-detector rates.

### W2: Robustness is shown against non-adaptive prompt sets only
The Table 3 caption says the results show "the potential to serve as an effective defense mechanism". Ring-A-Bell, MMA and I2P were not optimized against this erased model. Concept-erasure papers in diffusion were repeatedly broken by adaptive attacks; for VAR the paper itself notes that no adversarial benchmark exists. A white-box prompt-optimization attack and a multi-lingual/obfuscation test are the natural next step. Baselines are absent from Table 3.
- **Suggested Fix**: add baselines to Table 3, plus one adaptive attack (optimized prompt suffix) and a non-English test.

### W3: No limitations or societal-impact statement, and the nudity figures need handling
The paper has no limitations section or ethics statement (§6 ends with the conclusion), no discussion of dual-use (an erased/un-erased diff can be used to locate the capability), no comment on bias (which people or body types the erased model still renders), and no description of how explicit generated images in Figs. 4, 5, 10, 11 are handled.
- **Suggested Fix**: add a short limitations/ethics paragraph; blur or crop explicit outputs.

### W4: Concepts other than nudity are covered by one example each
Violence and hate (named in §1, "pornography and violence") are never tested, even though I2P contains them and the text-level claim ("sensitive concepts") is broad.
- **Suggested Fix**: add one violence or hateful-symbol concept evaluated on I2P categories.

### Assumption audit
(1) That a single lexical trigger ("naked") stands in for a concept (App. D); (2) that classifier accuracy on generated images measures removal rather than image degradation (ACCe near 0 could also arise if images become unrecognisable, which ACCi partly guards); (3) that behaviour at 1024² with Infinity-2B scales to larger VARs.

### Cross-disciplinary connections
Media-forensics practice evaluates removal with multi-detector ensembles; model-editing work in language models audits "ripple effects" on neighbouring concepts (a general technique, not a specific citation); the safety-case literature on layered defenses suggests pairing erased weights with output filters rather than treating erasure as the only barrier.

## Devil's Advocate

# Devil's Advocate Report

## Paper: Closing the Safety Gap: Surgical Concept Erasure in Visual Autoregressive Models
## Reviewer: Selin Orlowski, evaluation-methodology group, European research institute (fictional persona)

---

## Steelman
Concept erasure was designed for noise-prediction diffusion models; Infinity's bitwise next-scale generator breaks the assumptions. By teacher-forcing on the original model's tokens and masking already-correct bits, the authors obtain a cheap fine-tune that removes three kinds of concepts, resists three adversarial prompt sets, and beats four adapted baselines in both erasure and preservation.

## Core Argument Chain
1. Diffusion-style erasure losses fail on VAR because errors accumulate across scales (§4.1, Fig. 2).
2. Teacher-forced auxiliary tokens (VARE) fix this.
3. Bit-wise filtered CE plus KL preservation erases "surgically" (§4.2–4.3).
4. Table 1–3 show high erasure with little collateral damage and robustness.
∴ The method closes the safety gap for autoregressive text-to-image generation.

## Strongest Counter-Argument
The evidence supports "a fine-tuning recipe that removes three trigger words from one model with some unmeasured side effects", not "surgical concept erasure". The erasure target is a fixed lexical item: App. D says the c* prompts "include only the term 'naked' and exclude other semantically similar words", and the test prompts of Table 1 are LLM-written variants that "explicitly include the target concept" (§5.1). A model that learns "naked" ↦ "clothed" scores ≈ 97% on such prompts. The evidence for concept-level removal is Table 3 (adversarial sets) and Figs. 10–11, and Table 3 has no baselines, so it cannot show that the new loss, rather than any strong fine-tune, produces it. The "surgical" evidence in the same tables points the other way: benign body-part detections drop from 112 to 57 (Table 1) and from 419 to 146 on I2P (Table 3). The mechanistic story (error accumulation across scales; filtering of "over-optimized" tokens) rests on Fig. 2 and Fig. 3, each one prompt, and neither filter nor VARE is ablated quantitatively, while the only direct ablation (Table 4) compares against a baseline that is the authors' own VARE-MSE loss re-labelled AC-N. Every baseline is trained under hyper-parameters (lr 2×10⁻³, 500 iterations, Table 6) the authors developed for their method. The authors must show (a) that a loss-level difference remains after baseline tuning, (b) that the filter matters at matched erasure strength, and (c) that synonyms and neighbours behave as claimed, before "closing the safety gap" is more than a slogan.

Resolvability: all three need new but modest experiments; none contradicts the data.

## Editorial Decision Letter

Dear Authors,

Thank you for submitting "Closing the Safety Gap: Surgical Concept Erasure in Visual Autoregressive Models" to ICLR. Making next-scale text-to-image models safer after deployment is a timely goal, and we appreciate that you tackled a new model family with an inexpensive recipe.

**Overall Assessment:** The panel saw a credible first adaptation of concept erasure to Infinity-2B, with consistent gains over adapted baselines (Tables 1–3). The panel also found that the mechanisms presented as the contribution are not yet measured, that claims are broader than the evidence, and that several evaluation details are missing.

**Key Strengths Identified by Reviewers:**
1. A new, practically relevant setting and a cheap fine-tuning recipe on one GPU (R1-S1, R3-S1, R4-S1).
2. Breadth of concept types plus multi-concept and adversarial-prompt checks (R1-S2, R3-S2, R2-S4).
3. Loss design linked to the model's own training objective and informative ablations (R2-S2, R1-S4, R4-S3).

**Key Concerns Requiring Attention:**
1. The need for VARE and the value of the filter are shown only qualitatively or jointly with the loss change, and the Table 1 "AC-N" baseline is the VARE-MSE loss (CONSENSUS-3 and CONSENSUS-2).
2. Baseline fairness (no tuning described, shared hyper-parameters, UCE failure untested) and single-run reporting (CONSENSUS-2/4).
3. Claims are broader than the evidence ("97% of sensitive concepts", "closing the safety gap", "surgical" despite halved benign-content counts); closest autoregressive erasure work (EAR) is not differentiated (CONSENSUS-4/2).

**Critical Challenge (Devil's Advocate):** No CRITICAL issue was raised. The strongest objection is that the evidence supports erasing three trigger words on one model, not concept-level erasure, and that Table 3 lacks baselines.

**Decision: Borderline Reject (3).** The panel leans toward rejection because the experiments that would show why the method works, rather than that it works on the trained concepts, are missing, and because the conclusions are scoped beyond one model. The issues are fixable. A revision with the Priority 1 items below would plausibly be viewed more favourably.

Please refer to the Revision Roadmap below.

Sincerely,
Adaeze Lindqvist
Editor-in-Chief (meta-reviewer)
